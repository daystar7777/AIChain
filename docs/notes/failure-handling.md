# 장애 상황별 처리 (프로토타입)

작성: 2026-10-11 · 테스트: `tests/test_faults.py` (상황마다 일부러 고장을 내고 확인)

원칙: **노드 하나·에피소드 하나의 실패가 네트워크 전체를 멈추지 않는다.** 단, 체인 로그를 쓸 수 없을 때는 기록되지 않은 상태로 계속 움직이지 않도록 **멈춘다**(fail closed).

| 상황 | 처리 |
|---|---|
| LLM 제공자 429·5xx·네트워크 끊김·타임아웃 | 지수 백오프로 최대 5회 재시도(Retry-After 우선, 최대 60초). 실패하면 그 에피소드만 `provider_error`로 종료 |
| 제공자가 오류 본문, `failed`, 출력 없는 `incomplete`, 깨진 JSON을 돌려줌 | 제공자 오류로 변환해 재시도하거나 에피소드 종료 |
| 도구 호출에 call_id가 없거나 인자가 문자열이 아님 | 허용해서 보정 (call_id 생성, 인자를 JSON 문자열로) |
| 이전 출력(reasoning 등) 재전송을 제공자가 400으로 거부 | 원본 항목을 빼고 한 번 다시 보냄 |
| 어댑터 버그(예외) | 재시도하지 않는 오류로 바꿔 에피소드 종료. 다른 노드는 계속 |
| 도구 처리 중 예상 못 한 예외(버그, DB 문제) | 모델에게 "내부 오류"를 돌려주고 `tool_error`로 기록. 에피소드는 계속 |
| 같은 에피소드에서 도구 호출이 연속 3번 실패 | 에피소드 종료(`tool_errors`). 같은 실수를 반복하며 호출을 낭비하지 않게 |
| 에피소드 코드 자체의 버그 | 그 에피소드만 `error`로 종료, `episode_error` 기록, 노드 상태 정리 |
| 이벤트 폭주 | 남은 이벤트는 다음 주기에 처리(`busy` 기록), 예외 없음 |
| 저널 기록 실패(디스크 가득 참 등) | 무시하고 계속, stderr에 경고(처음 5번, 이후 100번마다) |
| **체인 로그 기록 실패** | **네트워크 정지**: 새 거래·블록·에피소드 중단, Bridge API는 503. 재시작하면 기록된 데까지 재생되어 일관된 상태로 복구 |
| 체인 로그 변조·손상(state root 불일치) | 시작 거부, 원인과 복구 방법을 출력 |
| 런타임 루프의 반복 오류 | 오류마다 대기 시간을 늘림(0.5초→최대 60초), 성공하면 초기화 |
| 하루 LLM 호출 상한 도달 | 상한(노드별·전체)의 20%(`--duty-reserve-share`)는 의무(우선순위 1~3: 판정, 분쟁·검토, 투표, 관리인·Bridge 질문, 답변)에만 쓴다. 연구·경제 점검·회고는 그 선에서 멈추고 아예 넣지 않음. 호출을 못 받아 `call_limit`·`budget`·일시적 `provider_error`로 끝난 의무는 버리지 않고 기다렸다가, 호출이 가능해지고 아직 유효하면(판정 중, 투표 중 등) 다시 처리. 하루가 지나거나 더는 유효하지 않으면 `duty_dropped` 기록 |
| 시작할 때 체인에 있는 계정의 키 파일이 없거나 다름 | 새 키를 만들지 않고 시작 거부(종료 코드 4), 백업에서 복원하라고 출력 |
| Brave 검색 상한 도달·API 오류 | 웹 오류로 모델에게 알림, 그날 검색 중단 |
| 웹 응답 형식 이상(결과 없음, http가 아닌 URL, 텍스트 없음) | 걸러내거나 웹 오류로 |
| Chromium 비정상 종료 | 다음 요청 때 자동 재시작 |
| egress 프록시에 이상한 요청 | 400으로 거절, 프록시는 계속 |
| SQLite 잠김 | 30초까지 대기 |
| 서비스 프로세스 비정상 종료 | systemd가 재시작(10분에 5회 넘으면 멈추고 로그 확인 필요). 체인·기억·도구·사용량은 디스크에서 복구 |
