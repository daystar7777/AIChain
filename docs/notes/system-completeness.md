# 시스템이 온전히 동작하기 위해 필요한 것 (2026-10-12 점검)

서버 운영 데이터와 코드를 점검해 찾은 빈 곳과 처리 방법.

| # | 빈 곳 (근거) | 처리 |
|---|---|---|
| 1 | **노드가 스스로 경제 활동을 하지 않는다.** 최근 에피소드 200개가 연구·회고·현상금뿐이다. 판매·구독·예금·대출·도구 매매는 이벤트가 없어서 한 번도 쓰이지 않았다 | 노드별로 엇갈린 **경제 점검(economy_tick)** 이벤트(기본 4시간). 잔액·예금·대출 만기·할당량·저장 공간·열린 시장 요약을 Core가 만들어 주고, 할 일이 없으면 바로 끝내라고 지시 |
| 2 | **요청마다 모든 도구 정의를 보낸다.** 도구 31~55개, 스키마 15~25k자, 호출당 입력 1.3만 토큰 평균 | **이벤트별 도구 범위**: 현상금 답변에는 답변·조회·웹·도구 실행만, 연구에는 웹·기억·노트만, 경제 점검에는 시장 도구만. 읽기 도구는 항상 |
| 3 | 평가(rate)가 현상금에서만 가능하다 | 정보 구매·구독·대출·도구 구매 요청도 평가 맥락으로 허용 |
| 4 | 산 도구가 명세와 다르게 동작해도 분쟁할 길이 없다(03 문서의 `tool` 분쟁) | `tool` 분쟁: 라이선스 보유자가 제기, 인정 시 설치비 환불·도구 판매 중단·작성자 감점 |
| 5 | 재시작하면 Bridge 질문 추적과 Policy Guard 지출 기록이 사라진다 | 디스크에 저장 |
| 6 | 운영 중 이상(공급량 불일치, 에스크로 불일치, 체인 정지, 서비스 오류)을 사람이 보기 전엔 모른다 | **자체 감사(audit)**: 매시간 공급량·에스크로·잠금·state root 재계산 검사, 이상이면 저널·관리인(텔레그램)에 알림 |
| 7 | 저널이 계속 커진다(LLM 프롬프트 원문) | 보존 정책: 기본 14일이 지난 LLM 호출의 프롬프트 원문만 지우고 요약은 유지 |
| 8 | 위 기능들을 실제 모델이 제대로 쓰는지 확인된 적이 없다 | 실제 모델로 경제 시나리오 실행 후 리포트 |
