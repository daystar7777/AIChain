# DeepSeek Harness의 자기 확장(플러그인) 방식 분석과 AIChain 도구 공방 반영

작성: 2026-10-11 · 대상: `~/deepseek_harness/deepseek-harness` (읽기만 함) · 관련: [05 검색·도구·플러그인](../design/05-tools-plugins.md)

## 1. 하네스가 하는 방식

DeepSeek Harness(dsh)는 "모든 것이 Cordis 플러그인"인 구조이고, 실행 중인 에이전트가 자기 런타임에 플러그인을 추가할 수 있게 하는 도구 묶음(`dsh-tool-cordis` + `dsh-cordis-host-runner`)을 둔다.

| 단계 | 하네스의 방식 |
|---|---|
| (a) 필요 감지 | 자동 감지 장치는 없다. 시스템 프롬프트 섹션(`tool:cordis`)이 "사용자가 무언가를 만들려 할 때만, 이 런타임에 붙는 임시 확장이 맞을 때만" 쓰라고 가르치고, 플러그인 개발 Skill을 먼저 불러오게 한다. 판단은 모델이 한다. |
| (b) 명세·코드 생성 | 모델이 순수 JavaScript로 `apply(ctx)`를 쓴다. 쓰기 전에 `cordis_inspect_list` / `cordis_inspect_query`로 **실제 런타임의 서비스·이벤트·도구 시그니처**를 조회한다. 이 카탈로그는 소스에서 자동 생성되고 CI에서 신선도가 검사된다. 추측한 API로 코드를 쓰지 않게 하는 것이 핵심이다. |
| (c) 테스트·검증 | `cordis_define`은 문법만 미리 컴파일해 보고 **실행하지 않는다**. 등록 경계에서 도구 스키마를 정규화하고, 틀리면 고칠 방법을 담은 오류를 돌려준다. 자동 테스트 케이스 실행은 없다. |
| (d) 등록·로드 | 플러그인 ID(모델이 3~6자 접두사, 호스트가 최종 ID 발급) 아래 **불변 패키지 버전**이 쌓인다. `cordis_run`(첫 실행·재시작·롤백) / `update`(버전 전환). 브라우저 쪽 코드가 있으면 사람 승인 대기, 승인은 이번 버전만 또는 이후 버전까지. |
| (e) 실패·롤백 | `currentPackageId`(마지막 성공)와 `nextPackageId`(시도 중·실패)를 따로 둔다. 업데이트 실패는 current를 바꾸지 않고 이전 버전도 자동 재시작하지 않는다. 진단은 `cordis_inspect_self`로 읽고, **같은 플러그인을 고친다**(대체 플러그인을 새로 만들지 않는다). |
| 격리·권한 | 호스트 코드는 `node:vm` 안에서 돈다. 문서가 스스로 "보안 경계가 아니다, bash 권한처럼 다뤄라"라고 명시한다. vm은 전역 오염과 API 오용을 줄일 뿐이다. 셸 명령은 별도 샌드박스(Linux bwrap→Landlock, macOS Seatbelt)를 쓴다. 정의는 세션·프로세스 한정이고 재시작하면 사라진다. 모든 정의 호출(코드 포함)은 세션 로그에 남는다. |

## 2. AIChain 05 문서(도구 공방)와의 비교

| 항목 | 하네스 | AIChain 05 문서 | 결정 |
|---|---|---|---|
| 불변 버전 + current/next 포인터 | 있음 | "수정은 새 버전, 이전 버전은 남음" | **가져옴**. current/next, run/update, 롤백 의미를 그대로 구현 |
| 실패한 업데이트가 current를 안 바꿈 | 있음 | 없음 | **가져옴** |
| 같은 도구를 고치기(대체 금지) | 프롬프트 규칙 | 같은 에피소드 3회 재시도 | **가져옴**. 같은 이름으로 새 버전 정의 |
| API 카탈로그 조회 후 코드 작성 | 생성 카탈로그 + inspect 도구 | 없음 | **다르게**. 도구가 쓸 수 있는 것이 작아서(입력 dict→출력 dict, 허용 모듈 목록) 카탈로그 대신 공방 안내 섹션과 정적 검사 오류 메시지로 알려줌 |
| 고칠 방법을 담은 오류 | 등록 경계 | 오류 리포트를 `<data source="workshop">`로 | **가져옴**. 정적 검사 결과마다 줄 번호와 수정 힌트 |
| 정의 시 문법 사전 검사, 실행 안 함 | 있음 | 정적 검사 → 테스트 실행 | **둘 다**. 정의 = 정적 검사 + (실행이 켜져 있으면) 테스트. 실행이 꺼져 있으면 `not-run`으로 기록만 |
| 자동 테스트 루프 | 없음 | tests.json 3개 이상, 전부 통과해야 등록 | **05 문서대로**. 통과한 버전만 활성화 |
| 필요 감지 | 프롬프트 + Skill | 없음 | **가져옴**. "반복 계산·검증이 보이면 도구, 일회성이면 만들지 말 것" 안내 |
| 사람 승인 | 브라우저 쪽 코드에만 | 플러그인 설치는 운영자 승인 | 05 문서대로 유지(플러그인 단계에서) |
| 실행 격리 | vm(보안 경계 아님) | gVisor 일회용 컨테이너 | **가져오지 않음**. vm 수준은 이 서버에 부족. 실행은 격리 환경을 켜기 전까지 비활성 |
| 런타임 자체를 고치는 플러그인 | 가능(ctx 전체 권한) | 금지: 도구는 Core·Policy Guard·고정 코어를 못 바꿈 | **가져오지 않음**. 노드 변경은 거버넌스로만 |
| 세션 한정, 재시작 시 소멸 | 그렇다 | 노드 체인 기록, 영속 | **다르게**. 도구 버전은 영속(SQLite)하고 코드 해시를 기억에 기록 |

## 3. 이번에 구현한 범위 (`aichain/workshop/`)

- `manifest.py`: 매니페스트(이름, 설명, 입출력 스키마, 네트워크 none 고정, 시간·메모리 한도, 허용 패키지 목록).
- `static_check.py`: AST 검사. 금지 모듈(os, subprocess, socket, ctypes, importlib 등)과 허용 목록 밖 import, eval/exec/open/getattr, dunder 접근, global, `def run(input, ctx)` 유무. 각 결과에 수정 힌트.
- `registry.py`: 도구 ID `<노드>.<이름>`, 불변 버전, current/next, run/update/롤백, stop, 소유자만 활성화·실행, 테스트 3개 이상, 통과한 버전만 활성화. SQLite 영속.
- `executor.py`: 기본값 `DisabledExecutor`(실행 안 함). `LocalDevExecutor`는 개발용이며 `AICHAIN_UNSAFE_LOCAL_EXEC=1`일 때만 생성되고 격리가 아니다(이 Mac의 테스트에서만 사용).
- 마스터마인드 도구: `tool_dev`, `tool_list`, `tool_activate`, `tool_run`(실행이 켜졌을 때만 노출). 시스템 프롬프트의 "도구 공방" 섹션이 언제 도구를 만들지 안내한다.
- 저널: `tool_defined`, `tool_activated` 이벤트.
- `--workshop` 플래그(데모·브릿지)로 켠다. 서버에서는 실행이 꺼진 상태로만 쓴다.

실행 격리안은 [tool-execution-isolation.md](tool-execution-isolation.md).
