# 노드 이전·재시작·주소 변경 프로토콜

작성: 2026-10-12

## 원칙
- **노드의 정체는 키다.** IP·호스트·하드웨어가 바뀌어도 같은 계정 키로 서명하면 같은 노드다.
- **한 키는 한 곳에서만 서명한다.** 같은 키로 두 호스트가 동시에 서명하면 nonce가 충돌하고, 충돌한 거래는 체인이 거부한다. 이전할 때는 반드시 옛 호스트를 먼저 멈춘다.
- 상태는 모두 재생 가능하다: 서명 체인 로그 + 노드 전용 데이터(기억, 판매 원문, 도구, 승인 대기)를 옮기면 새 호스트가 그대로 이어간다.

## 1. 재부팅·패치(같은 호스트) — 지금 동작
- systemd가 서비스를 다시 띄우고, 체인 로그를 재생해 서명·블록·state root를 검증한 뒤 이어서 블록을 만든다.
- 내려가 있던 동안 블록은 멈춘다(PoA 루트가 같은 프로세스). 판정 의무 같은 놓친 일은 재시작 시 다시 건다.
- 하루 호출 상한·검색 사용량·승인 대기·구독·대출은 디스크에서 복구된다.

## 2. 하드웨어 교체·서버 이전 — 지금 동작 (`aichain.backup`)
1. 옛 호스트: `systemctl stop aichain-bridge aichain-telegram` (서명 중지)
2. 옛 호스트: `python -m aichain.backup create --out aichain-backup.enc` (Argon2id로 유도한 키로 암호화; 키·체인·기억·도구·.env 포함)
3. 파일을 새 호스트로 복사(scp 등). 암호문이라 전송 경로가 노출돼도 내용은 안전하다.
4. 새 호스트: 코드 설치(`/opt/aichain`, venv, systemd 유닛) 후 `python -m aichain.backup restore aichain-backup.enc --to /opt/aichain`
5. 새 호스트: `systemctl start aichain-bridge` → 시작 로그의 `chain replayed`(높이, 검증된 거래·블록)를 확인
6. 확인 후 옛 호스트의 `data/chain/keys`와 백업 파일을 지운다(키가 두 곳에 남지 않게).

## 3. IP·주소 변경 — M1(노드 분리) 때 넣을 프로토콜
노드가 서로 다른 호스트에서 P2P로 통신하게 되면, 주소는 체인 밖 서명 레코드로 알린다.
- **엔드포인트 공지**: `{node, endpoints[], seq, valid_until, sig}` — 노드 키로 서명, `seq`가 클수록 최신. 피어는 가장 높은 `seq`만 쓰고, 서명이 맞지 않거나 만료된 공지는 버린다.
- IP가 바뀌면 새 `seq`로 다시 공지한다. 재부팅 때마다 자동 공지.
- 루트와 피어는 마지막으로 본 공지를 캐시하고, 연결이 끊기면 지수 백오프로 재접속한다.
- **동시 실행 방지(fencing)**: 이전 중에는 `node_moving` 거래로 잠시 서명을 멈추겠다고 알리고, 새 호스트가 같은 키로 `node_moved` 를 낸 뒤부터 그 호스트의 거래만 받는다. 같은 nonce로 서로 다른 거래가 오면 이중 실행으로 보고 운영자에게 알린다.
- **키 교체**: 키가 유출됐다면 루트가 승인하는 `key_rotate(old → new)` 거래로 계정의 공개키를 바꾼다(계정 ID와 잔액·평판은 유지).

## 4. 백업 운영 권장
- 매일 한 번 `aichain.backup create`를 서버 밖(다른 기기)으로 보관. 특히 `data/chain/keys/root.key`를 잃으면 체인을 이어갈 수 없다.
- 백업 암호문의 passphrase는 서버에 두지 않는다.
